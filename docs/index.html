KepchukAPI Technical Documentation

KepchukAPI is a high-performance, deterministic Central Server (CS) for AI character networks. It acts as the single source of truth for user subscriptions, token consumption, dynamic rate limiting, and bot authentication.

Core Architecture Principles

  • Pure C11 Cryptography: Zero external crypto crates. SHA-256 and HMAC-SHA256 implemented in pure C11, verified against NIST FIPS 180-4 and RFC 4231.
  • Constant-Time Execution: Hardened against side-channel attacks using volatile accumulators and subtle timing equivalence.
  • Asynchronous Rust Core: Powered by Axum, Tokio, and Tower for ultra-low latency routing.
  • Standalone Deployment: Compiles to a single static binary with embedded SQLite and zero external runtime shared libraries.

Quickstart

Build and start the server with Cargo:

# clone and start
git clone https://github.com/uglyaz0tix/kepchuk.git
cd kepchuk
cargo run --release

# test server liveness
curl http://localhost:8080/healthz

3-Layer Security Model

All protected endpoints enforce strict verification across three independent layers:

Layer Mechanism Failure Response
Level 1: Identity X-Bot-ID + X-API-Key. The API key is verified via its SHA-256 digest against the storage engine. 401 Unauthorized
Level 2: Proof of Key & TTL X-Timestamp (sliding 300s window) + X-Signature (HMAC-SHA256). 401 Unauthorized
Level 3: Anti-Replay X-Nonce (UUID or unique hex). Stored in an in-memory TTL cache for 5 minutes. 409 Conflict

Canonical Signature Formula

time_window = timestamp / 300
body_sha256 = hex(sha256(request_body))
message = bot_id + ":" + timestamp + ":" + nonce + ":" + body_sha256
signature = hex(hmac_sha256(bot_secret, time_window + ":" + message))

Note: If the request body is empty (e.g. GET requests), body_sha256 is the SHA-256 of empty bytes (e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855).

Bot Authentication Endpoints

POST /kep/auth/register

Registers a new bot identity and issues credentials (returned once).

// Request Body
{
  "bot_id": "yuki_chan"
}

// Response (200 OK)
{
  "bot_id": "yuki_chan",
  "api_key": "ak_live_7c3a9f0e8124483a9084c0e69bd89410...",
  "bot_secret": "sec_49b5c328de804f568f9b3e10fa493d9b..."
}
POST /kep/auth/rotate

Rotates the secret key of the authenticated bot. Requires all 3 auth layers.

Response (200 OK): {"bot_id": "yuki_chan", "bot_secret": "sec_new_..."}

Tokens & Billing Endpoints

GET /kep/subs/status/:user_id

Retrieves user balance, tier, and block status.

// Response (200 OK)
{
  "user_id": "user_123",
  "tokens": 1000,
  "tier": "free",
  "is_blocked": false
}
POST /kep/subs/consume

Atomically debits tokens from a user account for character messages or operations.

// Request Body
{
  "user_id": "user_123",
  "tokens": 150,
  "reason": "chat_message"
}

// Response (200 OK)
{
  "status": "success",
  "new_balance": 850,
  "notify_owner": false
}
POST /kep/subs/purchase

Webhook for payment processors to credit tokens.

// Request Body
{
  "user_id": "user_123",
  "package": "pro",
  "tokens": 500
}

// Response (200 OK)
{
  "status": "success",
  "user_id": "user_123",
  "new_balance": 1350
}

Python Integration Example

import time, uuid, hashlib, hmac, json, requests

def send_bot_request(base_url, endpoint, bot_id, api_key, bot_secret, payload=None):
    body_bytes = json.dumps(payload).encode('utf-8') if payload else b""
    body_hash = hashlib.sha256(body_bytes).hexdigest()
    ts = int(time.time())
    nonce = str(uuid.uuid4())
    time_window = str(ts // 300)

    message = f"{bot_id}:{ts}:{nonce}:{body_hash}"
    signed_data = f"{time_window}:{message}".encode('utf-8')
    sig = hmac.new(bot_secret.encode('utf-8'), signed_data, hashlib.sha256).hexdigest()

    headers = {
        "Content-Type": "application/json",
        "X-Bot-ID": bot_id,
        "X-API-Key": api_key,
        "X-Timestamp": str(ts),
        "X-Nonce": nonce,
        "X-Signature": sig,
    }
    return requests.post(f"{base_url}{endpoint}", data=body_bytes if payload else None, headers=headers)

Security Vectors & Verification

The test harness tests/security_check.py continuously audits 17 attack vectors:

  • Missing individual headers $\to$ 401 Unauthorized
  • Invalid API key $\to$ 401 Unauthorized
  • Past expired timestamp $\to$ 401 Unauthorized
  • Future skewed timestamp $\to$ 401 Unauthorized
  • Duplicate nonce replay $\to$ 409 Conflict
  • Body modification after signing $\to$ 401 Unauthorized
  • Forged signature bytes $\to$ 401 Unauthorized
  • Cross-bot impersonation $\to$ 401 Unauthorized
  • Negative balance injection $\to$ 400 Bad Request
  • Excessive balance drainage $\to$ 400 Bad Request
  • Consumption by blocked user $\to$ 403 Forbidden
  • Post-rotation retired secret invalidation $\to$ 401 Unauthorized
